\section{Alur Penelitian}
Alur penelitian digunakan untuk menggambarkan tahapan-tahapan yang dilakukan dalam penelitian ini secara umum, mulai dari tahap awal hingga tahap akhir. Diagram alur penelitian yang digunakan ditunjukkan pada Gambar \ref{fig:alur-penelitian}.

\begin{figure}[htbp]
    \centering
    \includegraphics[width=0.7\textwidth]{image3.png}
    \caption{Alur Penelitian}
    \label{fig:alur-penelitian}
\end{figure}

Adapun penjelasan mengenai langkah-langkah alur penelitian tersebut adalah sebagai berikut:
\begin{enumerate}
    \item \textbf{Identifikasi Masalah}: Penelitian diawali dengan proses identifikasi permasalahan terkait penentuan kelayakan \textit{cooling water} pada sistem operasional di PT PLN Nusantara Power UP Arun. Permasalahan difokuskan pada bagaimana menentukan status kelayakan air pendingin secara lebih sistematis dan terotomatisasi.
    \item \textbf{Studi Literatur}: Tahap studi literatur dilakukan untuk memperoleh landasan teori yang relevan, meliputi konsep kualitas \textit{cooling water}, standar parameter berdasarkan manual W{\"a}rtsil{\"a}, konsep klasifikasi dalam \textit{machine learning}, serta prinsip kerja algoritma \textit{Random Forest}.
    \item \textbf{Perumusan Metodologi}: Pada tahap ini dirancang metode penelitian yang akan digunakan, meliputi teknik pelabelan data, strategi praproses, metode pembagian data, pembangunan model klasifikasi, serta teknik evaluasi performa model.
    \item \textbf{Pengumpulan Data}: Data dikumpulkan dari laporan pemantauan kualitas \textit{cooling water} periode tahun 2025. Data diperoleh dalam format \textit{spreadsheet} yang memuat parameter pH, SC, Nitrite, Fe, Sulfate, dan Turbidity. Total data yang diperoleh sebanyak 217 entri data.
    \item \textbf{Pelabelan Data (Rule-Based)}: Proses pelabelan dilakukan secara \textit{rule-based} berdasarkan rentang standar minimum dan maksimum setiap parameter yang mengacu pada dokumen resmi W{\"a}rtsil{\"a}. Tahap ini bertujuan untuk menghasilkan dataset terlabel (Layak dan Tidak Layak).
    \item \textbf{Praproses Data}: Tahap praproses meliputi pemeriksaan kelengkapan data, penghapusan data duplikat, penanganan nilai hilang, konversi tipe data numerik, serta pengecekan \textit{outlier} untuk memastikan kualitas data.
    \item \textbf{Pembagian Data (Stratified 70:30)}: Dataset dibagi menjadi data pelatihan (\textit{training data}) dan data pengujian (\textit{testing data}) dengan rasio 70:30 menggunakan teknik \textit{stratified sampling} untuk menjaga proporsi distribusi kelas.
    \item \textbf{Pembangunan Model (Random Forest)}: Model klasifikasi dibangun menggunakan algoritma \textit{Random Forest} berdasarkan data pelatihan.
    \item \textbf{Evaluasi dan Analisis Hasil Model}: Kinerja model dievaluasi menggunakan \textit{confusion matrix} serta metrik \textit{accuracy}, \textit{precision}, \textit{recall}, dan \textit{F1-score}. Selanjutnya dilakukan analisis terhadap hasil model, termasuk identifikasi kontribusi parameter dominan berdasarkan nilai \textit{feature importance}.
    \item \textbf{Penarikan Kesimpulan}: Tahap akhir berupa penarikan kesimpulan berdasarkan hasil analisis serta penyusunan rekomendasi untuk pengembangan selanjutnya.
\end{enumerate}

\section{Analisis Kebutuhan Sistem}
Analisis kebutuhan sistem merupakan tahapan untuk mengidentifikasi seluruh kebutuhan dalam pembangunan sistem, baik kebutuhan fungsional, non-fungsional, maupun kebutuhan data.

\subsection{Analisis Kebutuhan Fungsional}
Analisis kebutuhan fungsional bertujuan untuk menjelaskan aktivitas apa saja yang terdapat dalam sistem dan interaksi oleh setiap pengguna.
\begin{enumerate}
    \item \textbf{Kebutuhan Fungsional Admin}:
    \begin{itemize}
        \item Admin dapat melakukan login untuk mengakses sistem.
        \item Admin dapat mengelola akun pengguna (Operator), meliputi menambah, mengubah, menghapus, dan mereset password melalui menu kelola user.
        \item Admin dapat melihat seluruh data hasil klasifikasi kelayakan \textit{cooling water}.
        \item Admin dapat mengakses dan mencetak laporan (\textit{report}) hasil klasifikasi berdasarkan periode waktu atau unit mesin.
        \item Admin dapat melihat informasi evaluasi performa model klasifikasi (akurasi, presisi, recall, F1-score, confusion matrix, dan feature importance).
    \end{itemize}
    \item \textbf{Kebutuhan Fungsional Operator (User)}:
    \begin{itemize}
        \item Operator dapat melakukan login untuk mengakses sistem.
        \item Operator dapat menginputkan data parameter kualitas \textit{cooling water} (pH, SC, Nitrite, Fe, Sulfate, Turbidity).
        \item Operator dapat menjalankan proses klasifikasi menggunakan model \textit{Random Forest}.
        \item Operator dapat melihat hasil klasifikasi berupa status ``Layak'' atau ``Tidak Layak''.
        \item Operator dapat menyimpan hasil klasifikasi ke dalam sistem.
    \end{itemize}
\end{enumerate}

\subsection{Analisis Kebutuhan Non-Fungsional}
Kebutuhan non-fungsional mencakup aspek keamanan, kinerja, keandalan, kemudahan penggunaan, dan kompatibilitas, serta kebutuhan perangkat keras dan perangkat lunak.
\begin{enumerate}
    \item \textbf{Keamanan (Security)}: Sistem menjaga keamanan data melalui autentikasi login dan pembatasan hak akses.
    \item \textbf{Kinerja (Performance)}: Sistem mampu melakukan proses klasifikasi dengan waktu respon yang cepat.
    \item \textbf{Keandalan (Reliability)}: Sistem berjalan secara stabil tanpa sering mengalami \textit{error}.
    \item \textbf{Kemudahan Penggunaan (Usability)}: Antarmuka sistem dirancang agar intuitif dan mudah dioperasikan.
    \item \textbf{Kompatibilitas}: Sistem dapat berjalan lancar pada berbagai browser populer (Google Chrome, Edge, Firefox).
\end{enumerate}

\subsection{Perancangan Penerapan Algoritma Random Forest}
Diagram alur proses ditunjukkan pada Gambar \ref{fig:rancangan-rf}.
\begin{figure}[htbp]
    \centering
    \includegraphics[width=0.65\textwidth]{image18.png}
    \caption{Rancangan Penerapan Algoritma Random Forest}
    \label{fig:rancangan-rf}

Tahapan dalam Gambar \ref{fig:rancangan-rf} dijelaskan sebagai berikut:
\begin{enumerate}
    \item \textbf{Input Data (Dataset Mentah)}: Pemuatan data laboratorium 217 entri.
    \item \textbf{Pelabelan Data (Rule-Based)}: Menggunakan aturan logika untuk menetapkan target Layak/Tidak Layak.
    \item \textbf{Preprocessing Data}: Pembersihan data dari \textit{missing values} dan duplikasi.
    \item \textbf{Pembagian Data (Stratified Split 70:30)}: Membagi dataset menjadi Data Training (151 sampel) dan Data Testing (66 sampel).
    \item \textbf{Cross Validation (5-Fold)}: Melakukan validasi silang 5 bagian pada data training.
    \item \textbf{Pelatihan Model Random Forest}: Pembangunan pohon keputusan.
    \item \textbf{Evaluasi Model (per Fold)}: Pengukuran rata-rata performa fold.
    \item \textbf{Pelatihan Model Final}: Melatih kembali model menggunakan seluruh data training.
    \item \textbf{Evaluasi Model Pada Data Testing}: Pengujian model final pada data testing.
    \item \textbf{Implementasi Model}: Integrasi ke backend Flask.
\end{enumerate}

\subsection{Variabel Penelitian}
Penelitian ini menetapkan variabel bebas dan variabel terikat:
\begin{enumerate}
    \item \textbf{Variabel Bebas} (Fitur Masukan):
    \begin{itemize}
        \item pH: Keasaman atau kebasaan air.
        \item SC (Specific Conductivity): Konsentrasi mineral terlarut.
        \item Nitrite: Konsentrasi inhibitor korosi.
        \item Fe (Besi): Indikator korosi material.
        \item Sulfate: Potensi pembentukan endapan sulfat.
        \item Turbidity: Tingkat kejernihan air.
    \end{itemize}
    \item \textbf{Variabel Terikat} (Target): Status kelayakan air pendingin (Layak atau Tidak Layak).
\end{enumerate}

\begin{itemize}

    \item FN: Data Layak diprediksi Tidak Layak.
\end{itemize}
